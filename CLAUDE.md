# CLAUDE.md

Guidance for working in this repo.

## What this is

Marketing site for EMJU (a consulting firm). Two marketing pages: front page (`/`) and
contact (`/contact`), plus standalone microprojects under `(projects)` — currently
`/pomodance`. No auth. TanStack Start (React 19) on Cloudflare Workers.

## Conventions

- **Content is data.** Marketing copy for the front page and contact page lives in
  `src/content/site.ts` — edit it there, not in JSX. Keep that file to site content only, so
  it stays easy to move to a CMS later; app UI strings (a microproject's buttons, dialogs
  and labels) belong inline in the components that render them. Shared facts about the
  company — its name, site and repo URLs — stay in `company` there, so a microproject
  crediting EMJU imports them rather than restating them.
- **Fonts:** use the `font-display` class (Instrument Serif) for headings, `font-ui`
  (Instrument Sans) for labels/nav/buttons. Body text defaults to Atkinson Hyperlegible.
- **Styling:** Tailwind v4 + daisyUI v5. The theme (`emju` / `emju-dark`) is defined in
  `src/styles.css`. Prefer daisyUI semantic colors (`primary`, `base-100`, `neutral`, …).
- **Server-only code** goes under `src/server/`. Read env via `getEnv()` (which wraps
  `cloudflare:workers`), never `process.env` at module scope. Keep DB / secrets inside
  server functions, never in loaders or components.
- **Validation** that must run on client + server lives in `src/lib` (pure, no imports of
  server modules) so it stays unit-testable. Code only one microproject uses stays in that
  project's folder instead.

## Microprojects

A microproject is a self-contained toy or tool that shares the deployment but not the
marketing chrome. Each one is a single folder under the `(projects)` route group:
`src/routes/(projects)/<name>/`. The parentheses make the group pathless, so the URL is
just `/<name>`.

- `index.tsx` is the route. Everything else in the folder is prefixed with `-`, which the
  route generator skips: `-lib.ts`, `-lib.test.ts`, `-styles.css`.
- The prefix is not optional on `.ts`/`.tsx`. The generator routes every `.ts`, `.tsx`,
  `.js` and `.jsx` file it walks into, so a bare `lib.ts` would publish a `/<name>/lib`
  route. It ignores `.css` either way, but prefix that too so the rule stays "the route is
  `index.tsx`, everything else starts with `-`".
- A microproject brings its own chrome. Set `staticData: { bareLayout: true }` on the route
  and `src/routes/__root.tsx` drops the site header and footer for it; the page is then
  responsible for its own full-height background and footer.

## Testing

- Add `data-testid` (or `aria-label`) markers to new interactive elements so scenes can
  target them by intent.
- Unit tests: co-located `*.test.ts` in `src/lib`, or `-*.test.ts` inside a microproject
  folder. E2E scenes: `scenetest/scenes/*.spec.md`.
- After a fresh `openTo`, allow for hydration before clicking handler-driven controls (the
  contact scene uses a short `wait`).
- **Give every focusable control a unique `id`.** Scenes rotate actors between pointer and
  keyboard navigation, and a keyboard actor reaches its target by pressing Tab. To notice a
  target it can never reach, scenetest compares the focused element's `tagName + id` against
  where it started — so controls without an `id` all collapse to the same identity (`A`,
  `BUTTON`), and a page whose first focusable shares a tag with a later one trips that check
  before it arrives. The `id`s on the nav, footer, hero and pomodance controls are load-
  bearing for that reason; dropping one can fail a scene that never mentions it.

## Gate before committing

`pnpm format && pnpm lint && pnpm typecheck && pnpm test && pnpm build`
(and `pnpm scene` against a running `pnpm dev` when touching the UI/contact flow).

## Gotchas

- `worker-configuration.d.ts` is generated by `wrangler types` (runs on `postinstall`); it's
  gitignored. Run `pnpm cf-types` after changing `wrangler.jsonc`.
- `src/routeTree.gen.ts` is generated. `pnpm dev` rewrites it on the fly; after moving or
  renaming route files outside a dev server, run `pnpm generate-routes` and commit the
  result. It also rewrites the `createFileRoute('…')` id in the moved file.
